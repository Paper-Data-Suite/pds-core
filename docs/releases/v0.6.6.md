## Teacher-facing fix

Long OneDrive/workspace paths may be readable by Python yet rejected by a Windows
browser, PDF viewer, or Explorer. Core now uses a short directory junction under
the current user's local application-data directory for the Windows default-app
handoff of sufficiently deep file/folder targets. It does **not** copy, migrate,
rewrite, rename, or modify the authoritative source. `open_local_path` still
returns the resolved canonical source path, never the viewer alias.

Successful return means the OS **accepted the launch request**, not that an
asynchronous viewer actually displayed the document. Caller UI must not report
verified display without additional evidence.

## Custody, privacy, and lifecycle

Core creates unpredictable, bounded junction names under per-user
`LOCALAPPDATA/PaperDataSuite/viewer-aliases-v1`. A junction exposes the same
source directory to processes under the user's existing filesystem permissions;
it is **not** a new authorization grant. Callers must continue applying their
own workspace containment, permissions, SHA-256 and source-authority checks
before calling Core. No source files are staged or copied.

Junctions persist across launcher-process exit so asynchronous viewers can
finish loading relative HTML/CSS and other resources. An eventual 30-day
stale-alias cleanup is best-effort and removes **only the junction**, never its
target. This is bounded retention, not a guarantee of immediate revocation or
zero local link residue. Periodic cleanup requires a subsequent Core open; it
is not a background service. Clean-up eligibility does not guarantee no app
still depends on that alias; a 30-day policy is therefore an operational
tradeoff, not a formal lease. No registry changes or drive mappings are needed.

Platforms other than Windows keep their existing OS launch behavior. On Windows,
short paths continue to call the shell directly. A too-long alias or a failure
to create a safe junction fails with `LocalOpenError`; Core does not silently
fall back to launching the original known-problematic long path.

sdist inspection, isolated installed-wheel and sdist acceptance, a real

synthetic qualification verifies junction behavior but does not independently
prove a GUI viewer displayed that particular synthetic document.

## Versioning and consumers

Core v0.6.6 is an additive Core 0.6 patch release. Existing Core APIs,
retained-source provenance, publication and module operations contracts remain
unchanged. Consumers such as Concord, ScoreForm, Quillan and Vitrine using
`open_local_path()` may need dedicated teacher-message/acceptance updates
and their own new releases. Their historical releases and published artifacts
must not be replaced or relabeled. The Suite's historical exact composition
remains immutable; a newer composition is qualified separately.
