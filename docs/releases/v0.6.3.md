# pds-core v0.6.3

**Release date:** August 24, 2026

**Status:** Supported additive Core 0.6 release after #219 post-merge qualification

PDS Core v0.6.3 expands the shared standards subsystem while preserving the
existing Core 0.6 routing, workspace, roster, Academic Period, publication,
registry, provider-diagnostics, module-operations, and grouping-signal
contracts.

The release adds durable standards-framework provenance/lifecycle metadata,
three additional bundled instructional-framework packs, and an English 11
course profile over the existing NJSLS ELA 11-12 standards.

## Architecture boundary

The intended dependency direction remains:

```text
teacher
  -> Paper Data Suite shell
      -> public Core shared services
      -> installed module public services
```

Core owns neutral shared authority. The suite shell owns exact release
composition, orchestration, aggregation, launch UX, backup/restore, and
teacher-facing presentation. Modules own their domain facts, records,
interpretation, grading/review behavior, and owner actions.

The standards expansion does not make Core a curriculum engine and does not
make Core responsible for suite release composition.

## Standards framework metadata

The shared standards library now supports:

```text
StandardsLibrary
├── standards
├── profiles
└── frameworks
```

through immutable `StandardsFrameworkMetadata` records.

Framework metadata can preserve:

```text
framework_id
source
title
authority
publisher
source_url
version
adoption_date
implementation_date
supersedes
license_name
license_url
redistribution_notes
```

Lifecycle dates preserve source precision as `YYYY`, `YYYY-MM`, or
`YYYY-MM-DD`.

Framework adoption, implementation, supersession, and individual
`StandardDefinition.active` state remain distinct concepts. Core does not
perform automatic framework currentness or legal-policy selection based on the
clock.

Legacy standards-library JSON without a `frameworks` member remains valid and
loads with an empty framework collection.

### 2023 NJSLS English Language Arts

```text
pack: njsls_ela_2023
135 definitions
3 profiles
1 framework
```

The reusable profiles are:

```text

english12_2023_njsls_ela
```

New Jersey publishes the upper high-school expectations as one `11-12` band.
English 11 and English 12 therefore reuse the same 67 durable standards rather
than duplicating definitions by local course.

Course-filtered selection recognizes membership in a matching course profile,
which allows English 11 use while preserving the previously released
definition-level metadata on the shared 11-12 records.

## Starter merge semantics

Starter installation now treats three record families atomically:

```text
StandardDefinition
StandardsProfile
StandardsFrameworkMetadata
```

The merge contract remains:

```text
missing durable identity
-> add

identical record
-> skip

same durable identity + different content
-> conflict

same durable identity + explicit overwrite
-> replace
```

`StarterStandardsInstallResult.has_conflicts` accounts for standard, profile,
and framework conflicts.

`changed_count` accounts for additions/overwrites across all three families.

A framework conflict cannot cause standards or profiles from the same attempted
starter merge to be partially written.

Starter installation itself creates no standards usage events.

## Migration from v0.6.2

No workspace migration is required merely to install v0.6.3.

Package installation does not automatically:

```text
install a starter pack
rewrite standards/library.json
change a framework edition
add English 11 to an existing workspace
record standards usage
```

Existing v0.6.2-style framework-less standards libraries remain readable.

If a workspace previously installed the v0.6.2-era ELA starter, explicitly
installing the v0.6.3 `njsls_ela_2023` starter performs an additive
reconciliation.

A representative previous state is:

```text
135 ELA definitions
2 profiles:
  english10_2023_njsls_ela
  english12_2023_njsls_ela
0 framework records
```

The v0.6.3 starter merge yields:

```text
Standards:
0 added
135 skipped
0 overwritten

Profiles:
1 added
2 skipped
0 overwritten

Frameworks:
1 added
0 skipped
0 overwritten
```

The added identities are:

```text
english11_2023_njsls_ela
njsls_ela_2023
```

The existing 135 definitions are not rewritten. Repeating the same install is
idempotent.

## Security, privacy, and source-content boundaries

Release tests, compatibility fixtures, and examples use synthetic data only.

Do not commit or publicly post real rosters, student IDs, student work, grades,
scans, classroom records, credentials, or private school/district information.

The standards starter resources are committed release data. Validation does not
scrape or download standards at runtime.

Framework licensing/redistribution fields record source/curator facts and are
not automated legal judgments.

See [`../../SECURITY.md`](../../SECURITY.md).

## Explicit non-goals

v0.6.3 does not add:

- revised 2026 New Jersey successor standards;
- CSTA standards;
- generalized first-class cross-framework mapping persistence;
- automatic AP/NJSLS equivalence;
- curriculum sequencing;
- mastery or grading policy;
- automatic framework currentness selection;
- suite release composition;
- suite launch orchestration;
- suite backup/restore;
- module-specific standards stores;
- mandatory sibling dependencies.

## Release artifacts and qualification boundary

The normal v0.6.3 distribution artifacts are:

```text
pds_core-0.6.3-py3-none-any.whl
pds_core-0.6.3.tar.gz
SHA256SUMS.txt
```

The release-preparation PR may produce candidate artifacts, but those bytes are
not automatically final.

After that PR is squash-merged, release qualification rebuilds the wheel and
sdist from the **exact merge commit**, recomputes their hashes, reruns installed
acceptance and released-consumer qualification, and only then authorizes tag
`v0.6.3` and GitHub Release publication.

If an artifact is rebuilt after qualification, its earlier hash is invalid as
release evidence and the rebuilt bytes must be requalified.
