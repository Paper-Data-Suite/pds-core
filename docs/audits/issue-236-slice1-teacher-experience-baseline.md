## 1. Purpose, method and evidence limitations

This document establishes the **as-is** baseline and ownership boundaries before any new Core public API is frozen. It records source-observed navigation, output, and input patterns and a **sampled**, not exhaustive, collision inventory. It deliberately makes **no claim** that a proposed Notes command, teacher-private store, shared administration menu, or shared header is already implemented or released. No production code, producer repository, schema, manifest, or published wheel is changed by this slice.

Evidence method: inspect GitHub branch heads, Core's released version and source, the accepted-but-not-yet-release-qualified Suite design, the affected issue umbrellas, and representative teacher-entry and prompt helpers in six producer applications. Citations below are source links **pinned to commits**, not mutable `main` links. This is a source audit, **not** installed-wheel, runtime-terminal, physical-classroom, or all-nested-screen qualification. The deeper per-prompt census is a subsequent integration/consumer gate; unknowns are explicitly retained.

### Cross-cutting collision / safety findings

1. **Shared input function does not imply shared prompt semantics.** Core, Concord and Portia mix *choice*, *field*, and *confirmation* reads in prompt helpers; interception must receive an explicit caller-declared eligible prompt kind. Guessing from prompt wording or `input()` is unsafe.
2. **`B/M/Q` and `A` already have established behavior.** Core `parse_navigation_choice` **raises** on enabled `M/Q`, returns enum for `B` and opt-in `A`. Adding `:notes` may not change existing exception semantics or unexpectedly unwind the owning module.
3. **`H` is local/conditional.** Concord and Portia expose it via their navigation adapters; implementations must preserve it where offered rather than treating all letters as globally reserved.
4. **Quillan `N/W` are active workflow operations**, not available global shortcuts; no bare `N` Notes fallback and no choice reinterpretation in student-review text fields.
5. **Presentation differs across modules.** Core has an ANSI-on-TTY fixed header; Quillan hardcodes green escape sequences; Concord, Meridian and Portia currently print plain names in observed header helpers; Vitrine has a plain main title. These are **as-is differences**, not completed UX conformance.
6. **Output/terminal capabilities vary.** A future shared renderer must respect `NO_COLOR`, redirected output, Windows capability, injected streams and screen ownership. No blanket terminal-clear, ANSI escape, or global stdout side effect is safe as a Core library import.
7. **Path/confirm hazards are high impact.** Scan paths, roster edits, school-year overwrites, grade/record approvals and student-support notes must remain literal field inputs and retain owner-specific authority.

### Release and migration guardrails

- Core has two public executables (`core`, `pds-core`); Suite has its own `pds` executable. **Do not repurpose** an existing CLI letter, flag, positional value or exit status in #236.
- A contract document is not an installed symbol. Until the Core implementation is published and its exact supported consumer combination qualified, Suite/producers must show the shared capability as **unavailable** (or use a clearly documented existing independent local feature), not fake an implementation.
- Core's display/context objects must never become an owner/authorization source. An actor label is attribution, not authenticated Notes ownership. The private Notes collection is **outside** the ordinary classroom workspace backup scope under the accepted design; an explicit Core export/restore contract is future #243 work.
- Do not claim a cross-repository transaction, silently change teacher-owned evidence, convert personal Tasks to module attention or use installed module availability as proof of academic readiness.
- Do not change the historical Suite #49 composition/trust contracts or duplicate Suite #15 orchestration. **Core #236 freezes a Core companion** to Suite's accepted product specification, not a separate complete suite-wide specification.
